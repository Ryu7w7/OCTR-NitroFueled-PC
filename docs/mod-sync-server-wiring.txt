NEW IN THIS REVISION
integration/ryunet-modsync/bridge.go is the integration entry point. It wraps the
tested coordinator/HTTP handler and adds an administrator kill switch. It starts
disabled. Repeated enable calls preserve hold deadlines. Disable releases the gate
immediately; re-enable discards prior room readiness. No bridge lock is held while
calling membership/authentication adapters, avoiding lock inversion with matchmaker
operations. The actual close hook takes an already locked room snapshot directly.

CONNECTIONS TO MAKE IN CURRENT SERVER
1. Instantiate once during server initialization:

   bridge, err := modsync.NewBridge(authenticateCurrentProof, lookupCurrentRoom)
   // Handle err as a configuration error, not by weakening authentication.
   bridge.SetEnabled(serverConfig.OptionalModSync)
   mux.Handle("/ryunet/modsync/v2/", bridge)

   authenticateCurrentProof(*http.Request) (string,error) calls YOUR CURRENT
   X-RyuNET-Proof verifier with nonce replay protection and timestamp validation.
   It returns the stable authenticated account ID. Do not return an unchecked nick.
   lookupCurrentRoom(accountID) (modsync.Room,error) returns your current membership,
   a room ID, a unique race-attempt Round, and countdown state.

2. At the actual race-start/lobby-close transition, while the matchmaker owns its
   normal room lock, construct a modsync.Room snapshot. Then:

   if bridge.BeforeRaceStart(snapshot, time.Now()) {
       // Defer this host close/start request using the existing retry mechanism.
       // Do not mark it accepted or enter the race yet.
   } else {
       // Existing start logic and missing-character fallback continue unchanged.
   }

   Do not call lookupCurrentRoom again inside this lock. The wrapper deliberately
   accepts the supplied snapshot and cannot recursively acquire membership locks.
   The host must retry a deferred close; if it does not, arrange a server retry at
   deadline. Returning false alone cannot send a new start message on its behalf.

3. Call bridge.RoomDestroyed(roomID) when removing a room. Assign a new Round on
   each race attempt, not each heartbeat or membership update. Wire the admin
   setting to SetEnabled. Disabling the feature must not disable normal races.

WHAT THE WRAPPER DOES NOT DO
It does not invent the current server's auth function names or room structs. It does
not claim a cached ZIP is loaded or bypass OCTR's fallback. It does not supply hot
loading, authenticated auto-rejoin or a live native countdown UI adapter.
See mod-sync-integration.txt for those remaining contracts and limits.
